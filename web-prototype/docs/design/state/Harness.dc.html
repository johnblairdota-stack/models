The harness

One .mjs per gate, whose header is often longer than its code — that is where a number survives its author's death. Assertions are letter-numbered, file-local and quotable (R1, E4b, X15c) so they can be cited from a commit. Do not "fix" a gate to make it green: if a change turns one red, that is a finding.

What every gate keeps

  • The arm — usually R0 or B0 — refuses a vacuous greenthe first assertion proves the file has something to measure, and SKIPs with a reason if not
  • Every assertion ships a control that must fail, and the control runs every runa check that fires on everything and one that fires on nothing look identical to a run that only asks the shipped arm
  • The control mutates the real artefactthe shipped file, the shipped projection — never a string the control wrote itself on the same line
  • Bands, not absolutesescape E1's hard 4 passed for a year and then failed on a generated house
  • Seeded determinismone seed, one deal, byte-identical twice. Sweeps are seeds × counts × policies, not one lucky run.

The runner

  • The gate list lives in harness/gates.mjs, oncea committed, top-level, unprefixed harness/*.mjs that names itself in a summary line and is not in GATES fails the run — two gates once sat unrun for want of a list entry
  • It never short-circuitsit spawns every gate and prints one suite total; it replaced an && chain that stopped at the first red
  • No assertion may ever live in itthe runner is a launcher and a tally
  • ~450 probes are kept on purposeharness/evidence/_*.mjs — a probe is the record of a finding, cited by name from the header of the source it explains. Do not delete one to tidy up.
What the suite could not see, and now can

A model may stand in for something that does not exist yet. It may never stand in for something that does.

The old discipline polices whether an assertion can go red. It says nothing about whether the thing underneath it is the thing that ships — which is how five Fatal bugs lived inside a fully green suite. The sentence now sits in wire-parity's header, where a gate's argument belongs.
